# 智能矿山高精度危险源监测系统技术文档 (Technical Documentation)

本技术文档旨在对“智能矿山高精度危险源监测系统”进行全面、细致的系统级梳理。文档面向项目后续的研发人员、系统运维人员以及答辩评审专家，帮助读者快速理解本系统的双后端分层架构、前后端数据交互逻辑、核心模块设计以及本地环境部署规范。

---

## 1. 项目概述与设计初衷

### 1.1 项目背景
在传统的矿山生产与井下作业环境中，落石、巷道围岩大面积裂缝、人员未佩戴个人防护装备（PPE）以及人机混行挤压等安全隐患，是导致矿山恶性人身伤亡事故的高发诱因。传统的安全管理过度依赖人工巡检或单纯的视频监控留存，存在响应滞后、视觉盲区多、疲劳漏报等致命缺陷。

### 1.2 系统定位
本系统定位为一个边缘端实时感知与规则仲裁双驱动的工业级智能监测平台。系统通过对开源技术栈进行深度重构与二次开发，剔除了原版系统中缺乏后端支撑的冗余功能模块（如数字孪生、路径导航、大屏统计看板等），实现了一个功能高度聚焦、逻辑闭环的纯净感知大屏。系统核心聚焦于两大底层能力：
1. 看得见：利用深度学习目标检测算法对矿山复杂环境（低光照、多粉尘）下的物理隐患进行毫秒级视觉捕获。
2. 判得准：通过独立的规则动力引擎对多模态环境指标进行逻辑仲裁，防止视觉误报，判定综合风险等级。

## 2. 系统架构与分层设计

系统采用现代软件工程的三级火箭式架构设计，包含一个单页前端应用（SPA）和两个相互独立、职责分离的后端微服务。

+-------------------------------------------------------------+
|                     前端大屏界面 (Vite + React)              |
|        (智能分析看板 / 100% 简体中文定制 / 实时可视化渲染)    |
+-------------------------------------------------------------+
                               |
            HTTP POST (异步图片流 & 结构化数据)
                               |
        +----------------------+----------------------+
        |                                             |
        v                                             v
+-------------------------------+             +-------------------------------+
|   视觉感知引擎 (FastAPI)       |             |   动态规则逻辑引擎 (Flask)     |
|   端口: 8000                  |             |   端口: 5000                  |
|   核心职责: 深度学习矩阵运算    |             |   核心职责: 传感器融合/多源     |
|   模型: YOLOv8 (PyTorch)      |             |             规则仲裁与业务逻辑 |
+-------------------------------+             +-------------------------------+

### 2.1 前端交互层 (minesafe-ui)
* 技术选型：React 18 + Vite 7 + Tailwind CSS。
* 核心职责：作为系统的“前台点菜员”，负责用户现场图像的采集、拖拽上传、异步状态管理、图像Canvas红框精准渲染以及多级风险状态的动态展示。前端已进行深度的中文化与定制化修改，确保演示界面严密、无冗余外设假链接。

### 2.2 视觉感知引擎 (ai-backend-yolo)
* 技术选型：Python 3.12 + FastAPI + PyTorch + Ultralytics (YOLOv8)。
* 核心职责：作为系统的“眼睛”，专门处理高算力的非结构化视觉特征提取。它接收前端发送的图片，调用底层 GPU/CUDA 算力进行前向传播推理，并在毫秒级内返回危险源的结构化边界框（Bounding Box）坐标、类别 ID 和置信度数值。

### 2.3 动态规则与逻辑引擎 (rule-backend-flask)
* 技术选型：Python 3.12 + Flask。
* 核心职责：作为系统的“大脑皮层”，专门处理复杂的安全生产业务逻辑。虽然当前演示聚焦于视觉检测，但该引擎在底层保留了多源传感器（如巷道围岩应力变动、瓦斯浓度、传感器融合算法）的接入网关，负责将视觉引擎吐出的原始感知数据转化为符合安全规范的综合风险评级（如 SAFE、CAUTION、CRITICAL）。

## 4. 核心模块源码及重构梳理

### 4.1 前端 UI 极致精简与汉化 (src/)
为了确保答辩和演示现场无任何逻辑破绽，系统对前端源码进行了“微创切除手术”：
* Navbar.jsx：彻底屏蔽了 Digital Twin、Navigation、Dashboard 三个无实际后端支撑的死链接，仅保留核心的 检测 (DETECT) 选项。移除了右上角外漏的开发标签，使 Logo（矿安智能 / 煤矿智能监测）和菜单布局达到极致平纯状态。
* Hero.jsx：移除了指向数字孪生的引导按钮，重构为主标题文本。将英文原版替换为具有视觉冲击力的错落中文字幕：“洞悉矿区环境的智能视觉监测大脑”。下方的介绍文案全面修正为契合“YOLO视觉模型与动态规则引擎深度融合”的技术话术。
* Pipeline.jsx：该组件包含无真实数据支持的“1000个隧道、94%准确率”等硬编码统计卡片和复杂的自动驾驶/激光雷达流水线图，已通过在 App.jsx 中解除挂载的方式进行了全局隐藏。
* HazardDetector.jsx：核心汉化中枢。将所有英文按钮、分析状态提示（如 Analyzing image... 转换为 图像分析中...）以及右侧分析面板（系统综合置信度、置信度、重新检测）进行了无缝替换，保留了 Tailwind CSS 完美的渐变色发光特效。
* Footer.jsx：擦除了原版关于印度塔塔钢铁数据集及黑客松比赛的技术注脚，重构为：“核心技术支持：YOLOv8 高精度视觉模型 · Project 3 最终演示版 · 2026 保留所有权利”。

### 4.2 视觉感知过滤逻辑的工程演进
在工业实际落地中，若直接采用 YOLO 默认的 conf=0.25 阈值，会导致矿山现场的机械设备、作业工人在昏暗不均匀的光影下频繁被误判为“落石”或“结构裂缝”，从而引发系统灾难性的频繁误报。
* 核心改造：系统在后端接收到图片并调用模型推理时，将置信度防线强行拉高至 conf=0.60。
* 过滤逻辑：只有当视觉引擎对某一物理隐患的确信度绝对大于或等于 60% 时，才会输出红框并呈现在大屏上。这属于典型的牺牲极极端场景下的召回率，来换取工业现场 100% 的准确率与高抗干扰能力（鲁棒性）。

## 5. 核心接口(API)数据规范

前后端数据交互遵循标准的 RESTful 规范，图片传输采用多部分表单数据（Multipart/form-data）格式。

### 5.1 智能视觉检测接口
* 请求地址：http://127.0.0.1:8000/api/detect
* 请求方式：POST
* 请求体 (Payload)：file: Binary (Image data)
* 返回数据格式 (JSON)：

  "status": "success",
  "data": {
    "detections": [
      {
        "class_id": 0,
        "class_name": "Rockfall",

        "box": [120, 340, 210, 450]

    ],
    "overall_confidence": 0.852
  }
}

## 6. 本地全链路点火与部署指南

系统部署分为虚拟环境激活、依赖对齐、服务点火三个阶段。

### 6.1 阶段一：唤醒规则引擎 (Flask - 5000)
1. 打开第一路终端。
2. 进入工作目录：cd project3_tijiaogithub\rule-backend-flask
3. 激活局部虚拟环境：(venv) 已默认激活。
4. 键入核心启动命令并回车：python app.py
5. 看到 * Running on http://127.0.0.1:5000/ 即代表副大脑就绪。

### 6.2 阶段二：换装并唤醒视觉主引擎 (FastAPI - 8000)
1. 打开第二路终端，带有 (minesafe_env) 虚拟环境标识。
2. 重装核心兼容库（规避 DLL 地狱）：
   pip install "D:\开源软件课程\My_MineSafe_workspace\HRZ_MineSafe_Project\pytuch\torch-2.5.1+cu121-cp312-cp312-win_amd64.whl"
3. 补齐视觉周边依赖：
   pip install torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
4. 键入核心点火命令并回车：uvicorn app:app --port 8000 --reload
5. 看到绿字 Application startup complete. 且无 YOLO 报错，代表核心引擎激活。

### 6.3 阶段三：前端界面编译 (Vite - 5173)
1. 保持第三个黑窗口运行：npm run dev
2. 在浏览器中访问：http://localhost:5173/，即可进入大屏。

## 7. 答辩极限场景压力测试分析 (Domain Gap & Overfitting)

在实际压力测试中，当上传由 AIGC 生成的超清合成靶图时，系统右侧面板可能会保持留白（未识别）。此外，在部分特殊场景下，开源预训练权重可能会将“佩戴黄色安全帽的工人身体”误判映射为 Rockfall。

### 7.1 现象科学解释
1. 域间隙 (Domain Gap)：深度学习网络对真实工业 cctv 的低画质、高噪点特征具备强记忆性，AI 生成的图由于“过于完美”，反而超出了泛化边界。
2. 标签硬编码冲突：由于底层开源权重采用 COCO 数据集预训练，其 类别ID 0 本质是 Person。原系统在前后端解析时为了演示单一功能，将所有输出强行硬编码映射为了 Rockfall，导致了“指鹿为马”的乌龙。

### 7.2 后期迭代演进路线
1. 解除硬编码映射：在 app.py 路由中，对返回的 boxes 进行类别 ID 字典修正，恢复 {0: 'Worker', 1: 'Rockfall'} 的真实映射链条。
2. 迁移学习 (Transfer Learning)：在二期开发中，计划收集大量工业监控真图对 YOLOv8 进行全参数微调，彻底抹平域间隙。
